# PRD

> 2026-09-20 재작성. 기존 PRD는 Figma 최신 결정과 어긋나는 부분이 많아(예: 숙소 상세 페이지 Out of Scope 기재) 폐기하고, Figma 와이어프레임 코멘트·백엔드 구현 확정 사항·팀에서 확정한 "추천 코스" 상세 기획을 근거로 다시 작성함. 근거가 불확실한 항목은 각주로 표시.

## 1. 제품 약속

PLANLOG는 사용자의 감성, 여행 타입, 도착 시간, 이동 방식만으로 강원도 하루 여행 코스를 자동 생성하고, 실제 방문 경험을 스탬프와 감정 기록으로 남기는 반응형 웹 서비스다.

핵심 약속은 세 가지다.

1. 검색보다 선택: 목적지를 직접 고르지 않아도 감성과 조건만으로 코스를 만든다.
2. 계획보다 실행: 여행 당일 길찾기, 스탬프 획득, 기록 저장까지 한 흐름으로 연결한다.
3. 저장보다 축적: 방문 경험이 기록 카드와 감성 지도에 누적된다.

## 2. 왜 만드는가

- 혼자 떠나는 강원도 여행은 정보 탐색 비용이 높고, 당일 실행 흐름이 끊기기 쉽다.
- 기존 여행 서비스는 장소 탐색과 숙소 검색에는 강하지만 감성 기반 하루 코스 자동 구성과 방문 기록 누적 경험은 약하다.
- 공모전 심사자와 일반 사용자 모두가 짧은 시간 안에 서비스 가치를 이해해야 하므로 반응형 웹 기반의 명확한 데모 경험이 필요하다.

## 3. 대상 사용자

- 혼자 강원도 여행을 준비하는 20~30대 사용자
- 여행 기록을 간단히 남기고 싶은 사용자
- 공모전 심사자 및 데모 체험 사용자(= 게스트 로그인 계정. 스탬프 위치 제한 없이 전체 장소 체험 가능)

## 4. 범위

### In Scope

1. 반응형 웹 랜딩과 핵심 소개
2. 4단계 무드 셀렉터(감성/동행자 유형/시작 날짜·시각/시작 장소)
3. 코스 자동 생성과 결과 화면
4. **추천 코스 화면 — 코스 재추천, 시작/종료, 장소·숙소 변경 및 추가** (5절 참고)
5. 코스와 가까운 숙소 추천 + **숙소 상세 페이지**
6. 저장한 코스, 나의 기록, 기록 카드 상세, 마이페이지
7. 위치·권한 기반 스탬프 5states
8. 심사자(게스트) 체험 모드 — 위치 권한 없이 모든 장소 스탬프 가능

### Out of Scope

1. 네이티브 앱 기능
2. 실시간 채팅, 여행 메이트 매칭 UI 고도화(백엔드 매칭 API는 존재하나 UI 우선순위 낮음)
3. AI 챗봇 기반 자유 대화형 코스 생성
4. 숙소 전체 검색 페이지(숙소 "상세"는 In Scope, 숙소를 처음부터 검색하는 목록 페이지는 미제공)
5. 다국어 전체 지원
6. 구글 로그인 (OAuth 클라이언트 발급 전까지 보류 — 카카오/게스트만 지원)

## 5. 추천 코스 — 상세 동작 정의

> 이 절은 실제 기획 확정 문구를 그대로 반영. 백엔드 구현 완료(2026-09-20).

### 5.1 재추천

- "다시 추천 받기" 클릭 시 **"저장하기 혹은 진행하지 않은 코스는 삭제됩니다."** 안내 문구 노출
- 근거: `POST /courses/generate` 결과는 저장하기 전까지 서버에 아무것도 남지 않음(스테이트리스). 저장(`POST /saved-courses`) 전 재생성은 이전 결과를 자연히 잃음 — 안내 문구는 프론트 UX, 백엔드 변경 불필요

### 5.2 코스 시작 / 종료

- **"코스 시작하기"** 버튼 클릭 → 코스 상태 **진행중**으로 전환, 진행중 코스에는 **"코스 종료하기"** 버튼 노출
- **"코스 종료하기"** 클릭 → 코스 리뷰 작성 모달 노출(리뷰 작성 없이는 완료 처리되지 않음 — Figma 와이어프레임 코멘트 확인)
- 상태는 날짜(`travelDate`)가 아니라 **명시적 버튼 액션**이 기준
- API:
  - `PATCH /saved-courses/{id}/start` — 대기중 → 진행중
  - 리뷰 작성(`POST /records` + `savedCourseId`) → 완료. 또는 `PATCH /saved-courses/{id}/complete`로 리뷰 없이 강제 완료도 가능(운영 편의용 예외 경로)
  - 상태값: `PENDING`(대기중) / `IN_PROGRESS`(진행중) / `COMPLETED`(완료) — ⚠️ 프론트 `architecture.md`의 기존 zustand 설계는 `WAITING`으로 명명되어 있어 연동 시 매핑 필요

### 5.3 위치/권한별 스탬프 활성화

관광지 상세(스탬프 버튼) 노출 상태는 5가지:

| 상태 | 조건 | 버튼 |
|---|---|---|
| 비활성 | 위치 권한 미허용 | 비활성화 디자인 + 사유 한 줄 |
| 비활성 | 현재 위치 ~ 장소 거리 ≥ 2km | 비활성화 디자인 + 사유 한 줄 |
| 활성 | 현재 위치 ~ 장소 거리 < 2km | 활성화 디자인 |
| 완료 | 이미 스탬프 수령함 | 수령완료 디자인 |
| 항상 활성 | 로그인 계정이 심사자(게스트)일 때 | 위치 권한 무관, 모든 장소 오픈 |

- API: `GET /stamps/eligibility?contentId=&curMapX=&curMapY=` — 실제로 찍지 않고 5states 중 하나(`ALREADY_STAMPED`/`REVIEWER`/`NO_LOCATION`/`TOO_FAR`/`ELIGIBLE`) + 사유 문구 반환
- 실제 스탬프 생성(`POST /stamps`)도 서버에서 동일 기준으로 강제 검증(클라이언트 위치 조작 방지 — 대상 좌표는 TourAPI 실제 좌표 기준)

### 5.4 장소 변경

- "해당 장소로 코스 변경하기" 클릭 → "변경하시겠습니까?" 확인 모달 → 확인 → 장소가 바뀐 코스 화면 노출
- API: `PATCH /saved-courses/{id}/items` (`day`, `order`로 대상 지정) — 교체 후 그 날 이동거리/시간/도착시각이 자동 연쇄 재계산됨

### 5.5 숙소 선택(추가)

- "숙소 선택하기" 클릭 → "현재 코스에 해당 숙소 추가하시겠습니까?" 확인 모달 → 확인 → 숙소가 추가된 코스 화면 노출
- API: `PATCH /saved-courses/{id}/items`에서 `order`를 생략하면 "추가" 모드로 동작 — 그 날 마지막에 새 숙소 항목 추가(장소 변경과 동일 엔드포인트, 파라미터로 분기)

### 5.6 숙소 상세

- "코스와 가까운 숙소" 목록에서 숙소 상세 페이지 제공 확정(Out of Scope 아님)
- API: `GET /accommodations/{contentId}` — 이름/주소/좌표/사진/전화/개요/혼행유형 + 체크인·체크아웃 시각/객실 수/취사 가능여부/주차/예약 URL/부대시설 목록
- 관광지 상세는 별도 API(`GET /spots/{contentId}`, 이용시간/쉬는날/주차/유모차/반려동물/신용카드 + 로그인 시 스탬프 방문 여부)로 분리 — 두 API의 필드 구성이 다름

## 6. 기능 요구사항

### Must Have

1. GNB: `PLANLOG | 코스 만들기 | 추천 코스 | 나의 기록 | 로그인`
2. 비로그인 상태 보호 진입 시 로그인 모달 노출
3. 카카오 로그인 CTA (구글은 보류)
4. 랜딩 Hero, 축제, 코스 생성 방식, 감성 지도 프리뷰
5. 무드 셀렉터 4단계: 감성(5종) / 동행자 유형(혼자·가족·반려동물·조용히, 4종) / 시작 날짜·시각 / 시작 장소(역·터미널 선택 또는 자동차)
6. 코스 자동 생성 로딩 상태와 데이터 활용 문구
7. 지도 + 일정표 기반 코스 결과, 추천 이유 카드
8. 추천 코스의 재추천/시작/종료/장소 변경/숙소 선택 흐름 (5절)
9. 장소 상세의 스탬프 5states UI (5.3절)
10. 저장한 코스 상태 3단계(대기중/진행중/완료)와 필터, 다가오는 여행 D-Day 카드, 스탬프 진행률
11. 완료 스탬프: 감성존 필터 + 최신/오래된순 정렬, 스탬프별 리뷰 감정 표시
12. 여행 기록(리뷰) 작성: 감정(고정 8종) + 한줄 평가
13. 나의 여행 성향 그래프 + 대표 여행 유형 뱃지(리뷰의 감성존 분포 기반)

### Should Have

1. 같은 코스를 걷는 사람들의 감정 리스트("코스 후기" 탭 — Figma 화면 미확정, 백엔드 미착수)
2. 존별 저장 코스 보기
3. D-Day 알림, 코스 리마인드 토글
4. 심사자 데모 상태 전환

### Could Have

1. 감성 성향 상세 분석
2. 공유 고도화
3. 버스터미널 좌표 정밀화(현재 지오코딩 기반 근사치)

## 7. 우선순위

1. 코스 생성 플로우
2. 추천 코스 결과 화면(재추천/시작/종료/장소·숙소 변경)
3. 스탬프(위치기반) 및 리뷰 작성 흐름
4. 저장한 코스/나의 기록/마이페이지
5. 심사자 데모와 보조 기능

## 8. 검증 기준

### 제품 검증

- 사용자가 첫 화면에서 10초 안에 서비스 목적을 이해할 수 있는가
- 사용자가 4단계 입력만으로 코스 결과에 도달할 수 있는가
- 심사자가 위치 인증 없이 스탬프 경험을 확인할 수 있는가
- 코스 시작→종료(리뷰)→저장한 코스 상태 전환이 화면 간 일관되게 보이는가
- 장소 변경/숙소 추가 후 동선(시간표)이 자연스럽게 갱신되는가

### 구현 검증

- 주요 라우트가 모두 존재하는가
- 입력 상태가 폼 검증으로 관리되는가
- 서버 상태와 클라이언트 상태 책임이 분리되어 있는가
- `.env`와 `.gitignore`가 비밀값 유출을 막고 있는가

## 9. 열린 이슈

- "코스 후기" 탭: Figma에 사이드바/탭 라벨만 있고 실제 화면 디자인 없음 — 디자인 확정 필요
- 프론트 상태 네이밍(`WAITING`)과 백엔드 상태값(`PENDING`) 불일치 — 연동 시 매핑 또는 네이밍 통일 필요
- 버스터미널 좌표: OpenStreetMap 지오코딩 기반 근사치(도로 중심점) — 실서비스 전 재검증 권장
- 동행자 유형 "가족과 함께"/"조용히 쉬고 싶어요"의 코스 생성 로직 반영 방식은 백엔드에서 합리적으로 판단해 구현(가족: 이동거리 축소+체류시간 확대, 조용히: 인기 스팟 감점) — 기획 의도와 다르면 조정 필요
